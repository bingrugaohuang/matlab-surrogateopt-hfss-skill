# 身份、缓存与故障恢复

本节是适配器实现约定，不是宣称本仓库已提供事务服务。实际实现需要在目标文件系统和 AEDT 运行时进行故障注入验证。

## 三类身份

| 身份 | 覆盖内容 |
|---|---|
| sim_id | 不可变模型模板、AEDT/求解设置、设计/setup/sweep、材料、端口/参考面、网格、变量 schema、映射规则与固定结构 |
| score_id | 评分器与目标原始文件哈希、频率网格、单位、插值/导数方法、权重/尺度、平移或容差规则 |
| run_id / 配置身份 | 本轮边界、预算、目录、种子来源、代码与协议版本 |

用明确的规范化编码再做 SHA-256。规定字段排序、UTF-8、数值表示、单位、负零与非有限数值处理；跨 MATLAB/Python 需要固定测试向量。不要假设两个语言的默认 JSON 序列化逐字相同。

原始曲线缓存键可由 `sim_id + 完整量化后的实际变量` 组成；评分缓存另加 `score_id`。改变评分允许复用已认证的同一曲线并重新评分；不能复用旧 Fval。

活动 `.aedt` 文件可能随着参数和求解数据变化，其实时文件哈希应作为审计状态，不宜直接作为所有点的固定仿真身份。采用空闲、已审阅的模板身份，再校验固定设置；受控 Save 成功后更新审计状态。Save 抛异常或显式失败时不能推进审计哈希。

## 最小请求与响应契约

请求：协议版本、run/job、sim/score 身份、setup、完整实际变量与单位。

响应：对应身份与变量、成功/失败类型、曲线相对路径及原始文件哈希、行数/网格/单位、实际读取的模型变量、求解质量证据、尝试次数和耗时。路径须解析后仍在指定输出根内；防止 `..`、绝对路径逃逸或链接指向活动工程。

不接受“最后修改的 CSV”“最新一条 done”作为结果匹配方式。旧响应可以存在，但不能被当作新 job 的完成证据。

## 发布与恢复

在同一目标文件系统写临时文件，完成写入并关闭句柄，再使用目标平台已验证的原子发布方法。目录改名/文件替换的语义和持久性不是跨平台保证；断电恢复还需考虑 flush/fsync。

顺序：原始曲线 → 元数据 → 可恢复的 prepared 事务 → 最终 done 响应。done 是读取入口，发布它前必须保证所引用数据已完整可读。相同 job 的相同结果可幂等重放；不同内容冲突要拒绝，不能覆盖。

| 中断点 | 恢复处理 |
|---|---|
| 票据已写但请求未发布 | 用已有票据/job 发布，不能另扣新设计 |
| 请求已工作但无完成证据 | 查服务端所有权、日志、超时策略；不立即启动第二次求解 |
| 曲线存在但元数据未完成 | 不能当缓存；隔离并检查事务状态 |
| prepared 完整但 done 缺失 | 验证全部身份与哈希后补发布，不重新求解 |
| done 完整但账本未更新 | 按 job 幂等补记 |
| CSV/JSONL/进度文件不同步 | 从权威事件/事务记录重建，不能宣称跨文件天然原子 |

Windows 老版嵌入式 Python 的重命名、.NET File.Replace 与 CPython 不一定相同。通过 Python 3 测试不能证明 AEDT 运行时行为。原工作流曾保留 JSONL/CSV/进度分步更新的局限，应诚实报告，不能因为曲线原子发布就说全部恢复问题已解决。
